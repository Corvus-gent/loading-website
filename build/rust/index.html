why try rust?

Better tools for stricter contracts.

language capability

Memory rules at compile time.

Rust's ownership checks manage memory without a tracing garbage collector. That can help make native memory use more predictable. JavaScript already manages memory too; this is not a claim that the old site was unsafe.

implemented structure

One set of explicit contracts.

Routing, sessions, votes, uploads and stored records have old-versus-new checks. Shared Rust code can serve native APIs and WebAssembly. These tests and clearer boundaries are valuable engineering work, not magic supplied by a language.

potential, not measured

Native work with less overhead.

Compiled server code may improve CPU-heavy work and memory use. We still need deployed API latency, throughput, cold starts and cost measurements. Network, storage and third-party waits do not disappear.

measured tradeoff

The browser must earn its bytes.

The shared Rust download fell from 1,265,266 to 681,962 compressed bytes. It is still heavier than the existing page scripts. WebAssembly can be a cost before it becomes a benefit.

three caches. three different stories.

Caching isn't a Rust feature.

Browser / CDN cache
The warm-reload comparison above shows reused HTTP assets in this local lab. CDN hit ratios, invalidation and real-user gains have not been measured.
Application / Redis / regional cache
Existing keys, TTLs and storage semantics are being preserved. A verified native regional recovery path is still open. There is no demonstrated hit-rate, origin-load or cache-cost improvement yet.
AI prompt cache
98.45% of recorded migration input tokens were cached. This is model context reuse, not website speed or a discount we can turn into a verified invoice.
